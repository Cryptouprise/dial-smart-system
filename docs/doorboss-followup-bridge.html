The follow-up bridge

A follow-up booked at a doorstep travels all the way into Dial Smart's own database and onto its Callbacks screen. Then it meets a door that is bolted shut for every user, by design. Three of the four stages below are built and proven. The fourth is a platform-wide launch lock, not a gap in the clone.

1. At the door

input

A rep knocks, books a follow-up, and ticks "They said it's OK to text them". That single tick is the consent record the whole bridge is gated on.

The verdict

Three of four stages are built and proven. A doorstep follow-up reaches Dial Smart's own database, correctly matched, consent-gated, DNC-gated, and visible on the Callbacks screen. There is nothing left to build on the door-to-door side.

The fourth stage is locked platform-wide. The browser refuses every path that could start a call, and the server hardcodes the callback automation off. This is deliberate: the code says the block is "outside the certified launch profile" and must stay unreachable until callbacks get their own atomic server-side contract.

So auto-dialing a door follow-up is not a bug in the clone. It is a launch-certification decision - seven gates, starting at launchSafety.ts:77. Lifting it is Charles's call, and the port needs no change to receive it.
