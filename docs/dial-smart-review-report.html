Dial Smart / DoorBoss: capability review and launch verdict

An independent review by a swarm of cheap frontier models (37 substantive lane reports, every claim cited to file:line), argued by an adversarial prosecutor and defender, and resolved by me. 01The verdict

Not garbage. Not gold. Gold ore, 7/10. This is 160,832 lines of genuinely engineered product: a real canvassing PWA, a real multi-carrier browser dialer, a real AI call coach, a real metered credit ledger, 199 migrations and 110 edge functions. It is not a wrapper, not a demo, not an iframe.

What it is not is sellable today - for a reason nobody had named until this review, and which is now the single most important fact in the codebase (Section 02).

02The trap: the live product and the repo have drifted apart

Deploying the current repo would newly disable more than 40 working functions - including the dialer.

Two audits disagreed. One said "nothing dials, a certification wall blocks every call." The other said "the wall is only on `main`, live is ungated." I verified both claims directly:

CheckCommandResult
Gates in the deployed snapshotscount "certified" in supabase/functions-live (**18 files**)0 occurrences
Gates in the working tree / maincount "NOT_CERTIFIED" in supabase/functions (**197 files**)73 occurrences, 40+ functions

supabase/functions-live/README.md:79-80 states it plainly: "the 503 *_NOT_CERTIFIED gates exist only on GitHub `main`, never on live." The live Supabase deployment is a 2026-07-01 bulk deploy (README.md:17-18) that predates the whole certification layer.

What this means in one line, for Charles: the app on the internet works because it is an older, ungated build. The code in the repo - the code every future deploy would push - has a fail-closed certification wall across telephony, AI, GHL, calendar, email, spam-checking and daily reporting (generate-daily-report is on the list). Ship the repo as-is and the product stops working. That is the real launch blocker - not missing engineering, not a garbage pile.

Not verified: the live state of the ~10 functions that are not in functions-live/ (ai-brain, ai-autonomous-engine, ai-workflow-generator, email-sender, ghl-integration, calendar-integration, elevenlabs-tts, predictive-dialing-engine). Their live-vs-main state is unknown from the repo alone.

04The case against, the case for, and the resolution

Prosecution

  • No paying customer can complete a working outbound call on the repo build: activation is locked in the browser (launchSafety.ts), the provider release table has deliberately no seed data (20260713150000_campaign_contact_release_gate.sql:6), and dispatcher force/callback paths return false (call-dispatcher/index.ts:15-25).
  • The door to door to dialer handoff writes a lead that nothing ever dials: scheduled_follow_ups has 0 references in call-dispatcher, and the only executor is a browser hook that logs "Here you would integrate with actual SMS/call systems" (useDispositionAutomation.ts:493).
  • ~55 edge functions hard-return false and 503; crons for follow-ups, stuck-call recovery and reconciliation are unscheduled.
  • None of the five claimed differentiators is a real moat - all copyable.
  • 199 migrations / 11 eras / god components / no service layer = expensive to change safely.

Defence

  • The gates are deliberate fail-closed air-locks against unauthorised telephony spend, TCPA penalties and cross-tenant leaks (src/lib/launchSafety.ts, _shared/tenant-context.ts:44-63). What cynics call "stubs" are compliance switches.
  • 10 named, citable assets, each a sellable feature with a 1-5 day switch.
  • Real moat is off-list: data gravity from 199 migrations / ~495 RLS policies, and carrier + GHL depth no competitor has at this price.
  • Retell dialer path is genuinely certified and working.
  • The doorstep-to-dialer continuum is a positioning no competitor can copy in a sprint.

Resolution (mine)

  • Defence wins on engineering. The prosecution's own evidence shows gates, not gaps: the code below every gate is real. "No working call path" is true of the repo build, not of the deployed product.
  • Prosecution wins on packaging. Nothing is metered, verified or sellable as a package today, and the D2D-to-dialer handoff genuinely dead-ends.
  • Both missed the decisive fact: live and repo have drifted apart (Section 02). Deploying the repo would be a regression, not an upgrade.
  • Verdict: gold ore, 7/10. Valuable, unfinished, and one bad deploy away from breaking itself.

07The next 10 steps, ranked by value / effort

  1. Ship the live coach as a paid, metered feature. 1d High
    A live AI whisperer is the headline JustCall and Aircall do not have. Add a usage row in coach-suggest, bill via credit-management.
  2. Run one paid Retell campaign end to end and verify the credits deduct. 2d High
    This is the core paid product - and the only way to prove the money path works.
  3. Freeze the deploy question. 0.5d Critical
    Do not push the repo to Supabase until the 73 gates are reconciled with live. Pick one: port the gates onto a staging project and turn them on deliberately, or strip them from main so a deploy cannot regress the product. This precedes everything else.
  4. Verify reporting and expose it read-only in the client portal. 2d High
    Clients buy proof. Add the missing call_logs indexes first.
  5. Ungate NL to campaign and close the loop to launch. 3d High
    This literally is the target sentence "tell it what you want, it creates the campaign". Output is draft-only, so the risk is low.
  6. Make pipeline sequences execute. 3d High
    Route through the ungated automation-scheduler. Follow-up is the retention hook.
  7. Enable the DoorBoss pack for pilot orgs. 3d High
    The wedge: a standalone canvassing subscription for door-to-door solar reps.
  8. Fix the door follow-up dead end. 2d High
    Create the campaign_leads junction row in enroll.ts and let the dispatcher's callback path read scheduled_follow_ups. Without this the flagship continuum silently drops every booked follow-up.
  9. Cold email: certify Resend or add an Instantly adapter. 3d Medium
  10. AI inbound: certify the Retell inbound path. 4d Med-High
    Missed-call recovery is a strong pitch and needs no new vendor.

Do NOT build yet

  1. Ads. Missing entirely and needs live spend + measurement to mean anything. Revisit after sequences and reporting prove ROI.
  2. Video calls. 5 days for a differentiator that does not win the first paying customer. Do it after the wedge is billing.
  3. Full AI-manager autonomy. The service-role tool surface must move onto _shared/tenant-context.ts first - that is the reason it is 503'd.
  4. More industry packs. The seam is decorative: 4+ central edits per vertical. Fix the registry before adding a 4th pack.
  5. Unblocking Telnyx/GHL/calendar/ElevenLabs AI-voice paths. All deliberately gated. Unblock when a customer pays for them, not before.

Three ways this could waste money

  • Unbounded spawned agents. Experienced today: four plain spawned reviewers burned about $1.60 in two minutes with no turn cap, versus about $0.03 per node inside the graph orchestrator. Guardrail: run agents as graph nodes with a completion contract, not open-ended spawns; cap turns and set the abort rule.
  • Auto-expansion on a deep plan. Seed 13 nodes grew to 170 in one earlier run. Guardrail: seed a wide, flat, mostly-independent node set and set an explicit dollar cap before launching.
  • Handing a model a huge file. The 350KB combined report into one agent is a money fire. Guardrail: pass the 34KB condensed digest plus a row count and a few sample lines, and let the agent read the repo itself.

09How this review was done, and what it did not check

Method

  • A shared brief (docs/dial-smart-app-map.md) enforced one review contract on every lane: cite file:line, mark FACT vs THEORY, state what you did not check, do not pad, be willing to praise.
  • 12 lanes (architecture, data, dialer, integrations, AI, quality, scale, security, UX, product, market, risk) seeded as a task graph; the graph grew itself to 170 nodes, 65 substantive reports harvested.
  • Models: deepseek-v4.1-flash, qwen3.8-flash, gemini-3.8-flash, glm-5.3-flash, minimax-m3.1-flash, ling-3.1-flash and others - many families reading the same material, so a claim only survives if several agree.
  • Then three independent judges: an adversarial prosecutor, a defender, and a launch-blocker auditor.
  • Every load-bearing claim in Section 02 is mine, re-verified by me with a counter over the repo - not taken from a model.

Honest limits

  • No live Supabase queries were made: all schema claims come from migration text, so "migration exists" is not the same as "migration applied".
  • The deploy-trap finding rests on the 18 files in functions-live/ plus the README. The ~10 functions never snapshotted are unverified.
  • No call was placed; no build, typecheck, or test suite was run in this review.
  • The review was cut short by budget: the security/tenancy lane, the UX lane, the scalabity lane and the arbiter node did not finish. Their scope is a real gap, not a clean bill of health.
  • Confidence: high on the architecture, data, gating and blocker findings; medium on market and effort estimates.

SUM UP. Dial Smart is gold ore, 7/10: 160,832 lines of real product - a canvassing PWA, a browser dialer, an AI call coach, a metered ledger - that is not sellable yet, and whose own repo would break its own live deployment. The fastest path to revenue is the coach and the dialer, metered and proven; the wedge is door-to-door solar; the trap to defuse first is the diverged deploy.
