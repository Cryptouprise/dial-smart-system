## Bugs found 11/02 (fix before re-running)
1. **The Supabase secrets API returns digests, not values.** `twilio_setup.py` with no label ("LIVE") reads that digest as the Account SID, so Twilio answers 401 "invalid username". `sbsecrets.py match-twilio` compares the digest to raw SIDs, so its earlier "matches NONE" result means nothing. Fix: find which `~/.mcp.json` Twilio account is the dialer's, either by comparing sha256(sid) with the digest (confirm the digest format first) or by matching the dialer's Twilio numbers (phone_numbers rows on Twilio) to each account's number list, read-only. Then run `python twilio_setup.py <LABEL>` and remove the LIVE default.
2. **Telnyx user_name must be letters and digits only.** FIXED in `scripts/ship/telnyx_setup.py` line 38 (`dsbp` + hex). Not re-run yet.
3. **The runbook's WEBHOOK_SECRET_TELNYX line is wrong.** Get the Telnyx public key (portal: Account Settings > Keys & Credentials > Public Key), set it as WEBHOOK_SECRET_TELNYX, and correct the runbook.
4. **Three Twilio voice webhooks returned 500 on every request. FIXED + REDEPLOYED 11/02.** `twilio-voice-status`, `twilio-voice-transcription` and `twilio-voice-twiml` 500'd on *every* method including `OPTIONS`, from the moment they were deployed. `OPTIONS` is answered before any handler code runs, so a 500 there means the module failed to LOAD, not that the signature check rejected — probe `OPTIONS` first whenever a function misbehaves. Cause: `_shared/voice-provider.ts` built a module-scope `const REGISTRY = { twilio: twilioProvider }` while `_shared/twilio.ts` imported `publicFunctionsBaseUrl` back from `voice-provider.ts`. That is an import cycle; the entries that imported `twilio.ts` before `voice-provider.ts` (exactly those three) evaluated `voice-provider.ts` while `twilio.ts` was still initialising, so the `REGISTRY` read hit the temporal dead zone: `ReferenceError: Cannot access 'twilioProvider' before initialization`, at module load. Fixed in commit `da242c46`: `publicFunctionsBaseUrl` moved to the new leaf module `_shared/public-url.ts` (re-exported from `voice-provider.ts` for compatibility) so `twilio.ts` no longer imports `voice-provider.ts`, and the provider map is now built lazily inside `providerRegistry()` so import order cannot matter. Verified by booting the REAL bundled ESM in Node behind a Deno shim (OPTIONS 200, GET/POST 403) and then live. **Follow-up:** `voice-call`, `voice-call-action`, `voice-call-events` and `voice-token` also import `voice-provider.ts` but import it *first*, so they never entered the dead zone and are working; redeploy them with the next ship so source and live match.
