### A. Outbound SMS flow
1. Entry point is the `sms-messaging` edge function; its `action` union is `'send_sms' | 'get_messages' | 'get_available_numbers' | 'check_webhook_status' | 'configure_webhook' | 'health_check'` (supabase/functions/sms-messaging/index.ts:19). FACT.
2. Auth: `get_available_numbers` and `check_webhook_status` are public (no user auth) (sms-messaging/index.ts:52, 58-61); all other actions require an `Authorization` header (sms-messaging/index.ts:62-66); a call bearing the service-role key plus `request.user_id` is treated as an internal service call (sms-messaging/index.ts:70-73); otherwise the bearer token is validated via `supabaseAdmin.auth.getUser` (sms-messaging/index.ts:76-86). FACT.
3. `send_sms` requires `to`, `from`, `body` (sms-messaging/index.ts:123-125). Numbers are stripped to digits/`+` and `from` is forced to start with `+` (sms-messaging/index.ts:130-132). FACT.
4. Sending number / provider selection: the `from` number is looked up in table `phone_numbers` (column `provider`) using `number.eq.<cleanFrom>` OR `number.ilike.%<last10>%` (sms-messaging/index.ts:135-140); `provider === 'telnyx'` routes to Telnyx, everything else routes to Twilio (sms-messaging/index.ts:142, 184, 235). FACT.
5. Credentials: Twilio path uses env `TWILIO_ACCOUNT_SID` and `TWILIO_AUTH_TOKEN` (sms-messaging/index.ts:93-94), sent as HTTP Basic base64 of `sid:token` (sms-messaging/index.ts:97-100, 242, 271). Telnyx path uses env `TELNYX_API_KEY` (sms-messaging/index.ts:103, 190). FACT.
6. Twilio path first verifies the `from` number exists in the Twilio account via `IncomingPhoneNumbers.json?PhoneNumber=...` and that `capabilities.sms` is true (sms-messaging/index.ts:238-256), then POSTs to `.../Messages.json` with `To`, `From`, `Body` (sms-messaging/index.ts:261-275). FACT.
7. Storage: before sending, a row is inserted into `sms_messages` with columns `user_id, to_number, from_number, body, direction:'outbound', status:'pending', lead_id, conversation_id, provider_type, metadata` (sms-messaging/index.ts:159-172). If `skip_db_insert` + `existing_message_id` are supplied, the insert is skipped and that id is reused (sms-messaging/index.ts:155-157). FACT.
8. On success the same row is updated to `status:'sent', provider_message_id:<Twilio SID>, sent_at` (sms-messaging/index.ts:291-295); on failure to `status:'failed', error_message` (sms-messaging/index.ts:279-286). If `conversation_id` is present, `sms_conversations.last_message_at` is updated (sms-messaging/index.ts:297-301). FACT.
9. A second outbound path exists inside `ai-sms-processor` action `generate_and_send`: it generates text with Lovable AI, picks provider from `phone_numbers` (ai-sms-processor/index.ts:455-463), sends via Telnyx (ai-sms-processor/index.ts:466-492) or Twilio `Messages.json` (ai-sms-processor/index.ts:494-521), then inserts into `sms_messages` with `status:'sent'`, `is_ai_generated:true`, `provider_message_id`, `sent_at` (ai-sms-processor/index.ts:524-539) and updates `sms_conversations.last_message_at` / `last_from_number` (ai-sms-processor/index.ts:542-550). FACT.
10. Status callbacks: no delivery-status callback URL is set on the outbound `Messages.json` POST (sms-messaging/index.ts:263-266; ai-sms-processor/index.ts:507-511) and no status-callback handler exists in the material. INFERENCE: message status is only ever `pending`/`sent`/`failed` as set synchronously by these functions.

### B. Inbound SMS flow
1. Receiver is edge function `twilio-sms-webhook` (supabase/functions/twilio-sms-webhook/index.ts:1-8). It is wired to Twilio by setting `SmsUrl` on each number (sms-messaging/index.ts:501-512; twilio-integration/index.ts:645, 691, 724, 779). FACT.
2. Payload is parsed as form-urlencoded, JSON, or raw text (twilio-sms-webhook/index.ts:326-343) and validated (phone regex, body ≤10000 chars, NumMedia numeric, MediaUrl0 parseable) (twilio-sms-webhook/index.ts:235-304). FACT.
3. Owner resolution is a 5-step cascade: (1) `phone_numbers.user_id` where `number = To` (twilio-sms-webhook/index.ts:397-406); (2) same table with `To` / `+digits` / `digits` variants (twilio-sms-webhook/index.ts:409-422); (3) `sms_messages.user_id` where `from_number = To` and `direction='outbound'` (twilio-sms-webhook/index.ts:425-439); (4) `sms_conversations.user_id` where `contact_phone = From` (twilio-sms-webhook/index.ts:442-455); (5) fallback — most recently updated row in `ai_sms_settings` with `enabled = true` (twilio-sms-webhook/index.ts:458-472). If none, the message is dropped and empty TwiML returned (twilio-sms-webhook/index.ts:474-482). FACT.
4. Conversation: found/created in `sms_conversations` by `user_id` + `contact_phone = From`; `last_message_at` updated and `unread_count` incremented (existing) or set to 1 (new) (twilio-sms-webhook/index.ts:489-527). FACT — so yes, inbound marks the conversation unread.
5. Duplicate suppression: if a row in `sms_messages` already has `provider_message_id = MessageSid`, the webhook returns early (twilio-sms-webhook/index.ts:530-544). FACT.
6. Storage: insert into `sms_messages` with `user_id, conversation_id, to_number:To, from_number:From, body, direction:'inbound', status:'received', provider_type:'twilio', provider_message_id:MessageSid, has_image, image_url, metadata` (twilio-sms-webhook/index.ts:547-567). FACT.
7. Lead linkage: `leads` looked up by `user_id` + `phone_number = From` (twilio-sms-webhook/index.ts:600-605). FACT.
8. A separate function `ai-sms-processor` also has an inbound path (`action: 'process_webhook'`) that stores inbound messages into `sms_messages` (ai-sms-processor/index.ts:86-164); the material does not show `twilio-sms-webhook` calling it. INFERENCE: `ai-sms-processor`'s webhook path is not currently wired to Twilio in the provided code.

### E. Inbound calls
1. `twilio-inbound-handler` is the Twilio voice webhook target; `twilio-integration` action `configure_voice_webhook` sets `VoiceUrl` (default `${SUPABASE_URL}/functions/v1/twilio-inbound-handler`) on all numbers or a supplied `phoneNumbers` list (twilio-integration/index.ts:974-1051). FACT. INFERENCE: no human-cell forwarding exists on the inbound-call path.
5. Call logging: `twilio-inbound-handler` inserts into `call_logs` (`user_id, phone_number:from, caller_id:to, status:'completed', outcome:'completed', notes`) after resolving `phone_numbers.user_id` by `number = To` (twilio-inbound-handler/index.ts:78-106). FACT.
